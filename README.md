# ΚΑΛΥΨΩ · Βάρδιες

Εβδομαδιαίο πρόγραμμα εργασίας πρατηρίου με αυτόματη δημιουργία + καταχώρηση ημερήσιων πωλήσεων καυσίμων (για μελλοντική πρόβλεψη παραγγελίας).

## Στήσιμο (μία φορά, ~15 λεπτά)

### 1. Supabase
1. Νέο project στο supabase.com (region: Frankfurt).
2. SQL Editor → επικόλλησε όλο το περιεχόμενο του `supabase_schema.sql` → Run.
3. Settings → API: κράτα το **Project URL** και το **service_role key** (το secret, όχι το anon).

### 2. GitHub
1. Νέο **private** repo, π.χ. `vardia`.
2. Ανέβασε όλα τα αρχεία του φακέλου (upload files → σύρε τον φάκελο ή τα αρχεία ένα-ένα, κρατώντας τη δομή φακέλων `app/`, `lib/` κλπ).

### 3. Vercel
1. Import το repo.
2. Environment Variables (και τα τρία σε Production + Preview):
   - `SUPABASE_URL` → το Project URL
   - `SUPABASE_SERVICE_ROLE_KEY` → το service_role key
   - `APP_PIN` → το PIN που θα βάζεις για είσοδο (διάλεξε 4–6 ψηφία)
3. Deploy.

### 4. Πρώτη χρήση
1. Μπες με το PIN.
2. **Προσωπικό** → πρόσθεσε τους υπαλλήλους: όνομα, τύπος (πλήρους/part-time), ποιες βάρδιες κάνει ο καθένας, ποιοι μπαίνουν στην εναλλαγή βραδινού.
3. **Ρυθμίσεις** → έλεγξε τα άτομα ανά βάρδια (προσυμπληρωμένα με το μοτίβο σου).
4. **Πρόγραμμα** → διάλεξε εβδομάδα, όρισε βραδινό + επόμενο βραδινό → «Δημιουργία προγράμματος» → διόρθωσε ό,τι θες με την παλέτα → Αποθήκευση → Εκτύπωση.

## Κανόνες που εφαρμόζει η αυτόματη δημιουργία
- 6 μέρες + 1 ρεπό για πλήρους απασχόλησης, part-time μεταξύ ελάχ./μέγ. ημερών.
- Βραδινός: Β Δευ–Σάβ, Ρ την Κυριακή. Ο επόμενος βραδινός: Ρ το Σάββατο, Β την Κυριακή. Ο προηγούμενος: Ρ τη Δευτέρα.
- Κυριακή: Π2 αντί Π4, Α2 αντί Α3, ο βραδινός μόνος 00:00–06:00.
- 11 ώρες ελάχιστη ανάπαυση ανάμεσα σε διαδοχικές βάρδιες (νόμιμο ελάχιστο).
- Οι part-time συμπληρώνουν όπου δεν φτάνουν οι πλήρους.
- Κελιά μαρκαρισμένα ως Ο (άδεια) διατηρούνται στη δημιουργία.

## Άδειες
Πριν πατήσεις «Δημιουργία», μαρκάρισε με Ο τις μέρες άδειας — ο αλγόριθμος τις σέβεται και δεν βάζει βάρδια εκεί.
