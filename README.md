# Turno — Πρόγραμμα βαρδιών & καύσιμα

Εβδομαδιαίο πρόγραμμα εργασίας πρατηρίου με αυτόματη δημιουργία, και
καταχώρηση/πρόβλεψη πωλήσεων καυσίμων.

---

## Εγκατάσταση σε ΝΕΟ Supabase (καθαρή βάση)

1. supabase.com → New project (region: Frankfurt).
2. SQL Editor → επικόλλησε **ολόκληρο** το `supabase_schema.sql` → Run.
   Στο τέλος του αρχείου υπάρχει σχολιασμένο `insert into stations` —
   ξεσχολίασέ το με όνομα, PIN και email του καταστήματος και τρέξ' το.
   (Εναλλακτικά, φτιάξε το κατάστημα από τη σελίδα εισόδου → «Νέο κατάστημα».)
3. Settings → API: κράτα το **Project URL** και το **service_role key**.

## Αναβάθμιση ΥΠΑΡΧΟΥΣΑΣ εγκατάστασης

Τρέξε με αυτή τη σειρά στο SQL Editor:

1. `migration_1_hardening.sql`
2. `migration_2_residual.sql`
3. `migration_3_integrity.sql`
4. `migration_4_month.sql`
5. `migration_5_security.sql`

Τα migrations είναι μη καταστροφικά και ασφαλή να ξανατρέξουν.
Το migration 5 μετατρέπει αυτόματα κάθε παλιό PIN σε ασφαλές hash στην επόμενη
επιτυχημένη είσοδο. Ο χρήστης θα χρειαστεί απλώς να συνδεθεί ξανά μία φορά.

Rollback (αντίστροφη σειρά): `rollback_5_security.sql`, `rollback_4_month.sql`, `rollback_3_integrity.sql`,
`rollback_2_residual.sql`, `rollback_1_hardening.sql`.

## Vercel

Environment Variables:

- `SUPABASE_URL`
- `SUPABASE_SERVICE_ROLE_KEY`
- `SESSION_SECRET` (συνιστάται — τυχαίο μυστικό 32+ χαρακτήρων για τα sessions·
  χωρίς αυτό χρησιμοποιείται προσωρινά το service-role key)
- `SIGNUP_CODE` (**απαραίτητο** αν θέλεις να επιτρέπεται δημιουργία νέων
  καταστημάτων· χωρίς αυτό το signup παραμένει κλειστό)
- `RESEND_API_KEY` και `MAIL_FROM` (προαιρετικά — για ανάκτηση PIN με email)

Τα νέα PIN πρέπει να έχουν 6–12 ψηφία. Τα υπάρχοντα 4ψήφια PIN συνεχίζουν να
λειτουργούν και αναβαθμίζονται σε hash στην πρώτη είσοδο.

## Tests & Simulations

```
npm install
npm test        # unit + integration tests
npm run simulate  # 3 monthly simulations (exit 1 σε πρόβλημα)
```

Τα tests καλούν **τις ίδιες** functions με το production code
(`lib/monthSave.js`, `lib/fuelCalc.js`, `lib/monthPlan.js`) — δεν υπάρχει
test-only αντίγραφο λογικής.

## Βασικοί κανόνες προγράμματος

- Πλήρους απασχόλησης: αυστηρά `work_days` μέρες (6 ή 5) ανά εβδομάδα.
- Part-time: εύρος από το προφίλ, ή ακριβής εβδομαδιαίος στόχος.
- 11 ώρες ελάχιστη ανάπαυση μεταξύ διαδοχικών βαρδιών.
- Όριο ταυτόχρονης παρουσίας προσωπικού (ρυθμιζόμενο).
- Νυχτερινό μπλοκ: Β Κυριακή → Β Δευ–Σάβ → Ρ Κυριακή → Ρ Δευτέρα.
  Ο επόμενος βραδινός παίρνει **υποχρεωτικά Ρ το Σάββατο** πριν από το μπλοκ.
  Μοναδική εξαίρεση: όταν ξαναεπιλέγεται ο εργαζόμενος που μόλις ολοκλήρωσε
  το προηγούμενο μπλοκ (A → B → A) — τότε ισχύει μόνο ο έλεγχος 11ώρου.
- Ακριβώς μία νυχτερινή βάρδια (Β) ανά ημερομηνία.
- Μετά τη δημιουργία τρέχει φάση **rebalance**: ντετερμινιστική αναζήτηση
  αλυσίδων μετακινήσεων (έως 3 βημάτων) που κλείνει ακάλυπτες βάρδιες και
  φέρνει τους εργαζομένους στον εβδομαδιαίο στόχο τους, χωρίς να παραβιάζεται
  κανένας κανόνας. Αν δεν υπάρχει νόμιμη λύση, το εξηγεί με warning.
- Η άδεια (Ο) αντικαθιστά ή όχι το εβδομαδιαίο ρεπό — ρυθμιζόμενο.
- Οι εργαζόμενοι δεν διαγράφονται ποτέ, μόνο απενεργοποιούνται.

## Μηνιαίο πρόγραμμα

Στη σελίδα Προγράμματος υπάρχει εναλλαγή **Εβδομάδα | Μήνας**.

Το Month mode είναι orchestration layer πάνω στον ίδιο weekly engine: για κάθε
πλήρη (Δευτέρα-based) εβδομάδα που τέμνει τον μήνα καλείται ο ίδιος
`generateWeek` → rebalance → `validateGrid`, μεταφέροντας το πραγματικό
cross-week state (τελευταία Κυριακή, κάτοχος νυχτερινού, προσωρινό history).

- Μήνας που ξεκινά μεσοβδόμαδα: η πρώτη εβδομάδα ξεκινά από την προηγούμενη
  Δευτέρα· οι ημέρες εκτός μήνα εμφανίζονται αχνές.
- Νυχτερινές: αυτόματο rotation με σειρά που ορίζεται στις Ρυθμίσεις, ή
  χειροκίνητη επιλογή ανά εβδομάδα. Το rotation δεν μηδενίζεται στην αλλαγή
  μήνα και συνεχίζει από τον **πραγματικό** τελευταίο κάτοχο.
- Αν ο επόμενος του rotation δεν μπορεί (άδεια/σύγκρουση), παραλείπεται με
  ρητό warning και αναλαμβάνει ο επόμενος διαθέσιμος.
- Το «Δημιουργία μήνα» παράγει **προσχέδιο** — τίποτα δεν γράφεται στη βάση
  μέχρι το «Αποθήκευση μήνα».
- Υπάρχουσες αποθηκευμένες εβδομάδες διατηρούνται από προεπιλογή και **δεν
  ξαναγράφονται καθόλου** στο Save — χρησιμεύουν μόνο ως state για τις επόμενες.
- Ο έλεγχος καταλληλότητας βραδινού καλύπτει **ολόκληρο** το μπλοκ (Κυριακή +
  Δευτέρα–Σάββατο της επόμενης εβδομάδας), όχι μόνο την Κυριακή.
- Χωρίς προηγούμενο αποθηκευμένο μπλοκ, ο τρέχων βραδινός επιλέγεται ρητά
  πριν το Generate.
- Το Save Month τρέχει server-side τον ίδιο validator με το weekly Save.
- Ο κάτοχος του νυχτερινού μπλοκ υπολογίζεται **πάντα από το grid** στον
  server — ποτέ από τιμή που στέλνει ο browser.
- `preserve: true` = καμία εγγραφή. Μια αποθηκευμένη εβδομάδα που
  επεξεργάστηκε ο χρήστης **γράφεται** κανονικά.
- Οι εβδομαδιαίοι στόχοι part-time αποθηκεύονται για **όλες** τις εβδομάδες
  του request, ακόμα και για τις preserved.
